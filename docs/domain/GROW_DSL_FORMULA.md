# Grow comment-DSL and typed-action reference

`POST /grow/{id}/{buy,sell,dividend,payback,cashflow,deposit}` (GROW-3/4/5, PLAN.md D-16) replace hand-written writes to `Transaction.comment` — the legacy `"Buy Share MSFT 10 x 25;"` style DSL the Grow investment tracker's UI generates and parses via `split(' ')` positional indexing across `src/app/panels/add/add.component.ts` and `src/app/panels/info/info.component.ts` (27 call sites total). Each typed action calls a pure calculator in `packages/domain/src/grow/actions.ts`, which in turn generates the comment string via the regex-based parser/generator in `packages/domain/src/grow/dsl.ts` — the same canonical format the existing (untouched) Angular UI already reads, so the two stay compatible without migrating the UI itself.

## Confirmed legacy formats

| Statement       | Canonical format                                                                                                              | Generated by                                                            |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Buy Asset       | `Buy Asset <title> 1 x <totalAmount>;` (or `<quantity> x <unitPrice>;` when bought by units)                                  | `add.component.ts`, `grow.component.ts`'s `buyProject`                  |
| Buy Share       | `Buy Share <title> <quantity> x <price>;`                                                                                     | same                                                                    |
| Buy Investment  | `Buy Investment <title> <deposit> <mortgage>;` (no `x`)                                                                       | same                                                                    |
| Sell Asset      | `Sell Asset <title> 1 x <amount>;` (or `<quantity> x <unitPrice>;`)                                                           | `sellProject`                                                           |
| Sell Share      | `Sell Share <title> <quantity> x <price>;`                                                                                    | same                                                                    |
| Sell Investment | `Sell Investment <title> <deposit> <mortgage>;`, optionally prefixed `Payback Liabilitie <amount> <credit>; `                 | same                                                                    |
| Dividend        | `Dividende Share <title> <quantity> x <price>;` — no state mutation                                                           | `dividende`                                                             |
| Payback         | `Payback Liabilitie <amount> <credit>;` (bare `Liabilitie <amount> <credit%>;` is an edit-flow-only, percent-capable variant) | `paybackProject`, `add.component.ts`'s generic `isLiabilitie` prefixing |
| Cashflow        | `CASHFLOW <cashflow>` optionally ` - CREDIT <credit>` + `;`                                                                   | `cashflowProject`                                                       |
| Deposit         | `Deposit <amount>;`                                                                                                           | `depositProject`                                                        |

A financing liability attached to **any** buy kind (not just Investment) prepends a bare `Liabilitie <loan> <credit>;` statement, joined with a single space (each statement already carries its own trailing `;`) — confirmed by reading `add.component.ts`'s generic `isLiabilitie` handling, which fires for Asset/Share/Investment buys alike. An Investment sell's attached payback instead prepends `Payback Liabilitie <amount> <credit>;`, built inline only for that one case.

Two historical dialects are still _parsed_ (for reading old transactions, e.g. a future P&L report) but never _generated_ by the typed actions:

- `CASHFLOW: <amount>;` (colon form) — an `add.component.ts`-only display side effect when manually executing a Sell Investment via the Add panel, not part of `grow.component.ts`'s own generation.
- Percentage-suffixed `Liabilitie`/`Payback Liabilitie` credit or amount tokens (`Liabilitie 500 20%;`) — an edit-flow-only convenience; resolving one requires the referenced liability's value at parse time, which isn't in the string itself.

## The multi-word-title bug this rewrite fixes

Every existing parser uses fixed positional array indices (`comment.split(' ')[2]`, `[3]`, ...), so a Grow project title containing a space silently corrupts every field after it — e.g. `"Buy Share Global Tech ETF 10 x 25;"` would misparse `quantity` as `"Global"`. The new parser (`packages/domain/src/grow/dsl.ts`) anchors each format with a regex whose greedy `(.+)` title capture backtracks against a _fixed_ trailing token pattern (e.g. `^Buy Share (.+) (\S+) x (\S+);?$`), so the title consumes exactly up to that fixed suffix regardless of how many words it contains.

## Typed actions and their mutation semantics

Confirmed by reading `add.component.ts`'s comment-parsing blocks directly — `grow.component.ts`'s own `buyProject`/`sellProject`/etc. only pre-fill the Add-Transaction panel; the state mutation happens when that pre-filled transaction is actually submitted, which is the logic these typed actions now replace outright.

- **Buy** (`packages/domain/src/grow/actions.ts`'s `calculateBuyAsset`/`calculateBuyShare`/`calculateBuyInvestment`): upserts the linked Asset/Share/Investment by the project's own title-as-tag, reduces the recorded transaction/`Grow.amount` by any attached financing loan, and — for Investment — always creates/updates the companion `M-<title>` mortgage liability. A financed buy also reflects the resulting debt onto the Grow project's own `liabilitie` field (not just the standalone Liability record), so a later `payback` or `sell`-with-payback has something to act on.
- **Sell** (`calculateSellAsset`/`calculateSellShare`/`calculateSellInvestment`): decrements the linked entity, removing it once it reaches zero; an Investment sell may include a `payback` to settle an attached liability atomically with the sale, with the transaction amount set to the actual net sale proceeds.
- **Dividend** (`calculateDividend`): produces a transaction only — confirmed no Share/Grow state mutation (a dividend doesn't change a holding's quantity or price).
- **Payback** (`calculatePayback`): available whenever a Grow project has an attached `liabilitie`, regardless of kind (matches `grow.component.ts`'s `paybackProject()`, which has no kind check). Zeroing both the liability's amount and credit removes it and sets `liabilitie` to `null`.
- **Cashflow**/**Deposit** (`calculateCashflow`/`calculateDeposit`): produce a transaction only, confirmed by reading both `grow.component.ts` and the exhaustive `add.component.ts`/`info.component.ts` parsing sweep — neither format has any downstream state mutation anywhere in the app.

## Three deliberate corrections (PLAN.md D-9)

Each because the source's own behavior is inconsistent with itself elsewhere in the same file — not a redesign:

1. **Buy Share's "no existing share" branch used the un-reduced (pre-loan) amount** for `Grow.amount`, while its "existing share" branch and both of Buy Asset/Buy Investment's own branches use the loan-reduced amount. The typed action always uses the reduced amount, matching every other branch.
2. **Sell Investment's transaction amount was built from a stray leftover value** (`sellProject`'s initial `amountTextField = '1'`, still present when `add.component.ts`'s Sell Investment block ran) **plus profit**, rather than the actual sale proceeds. The typed action returns the economically correct net profit (deposit minus any attached payback) as the transaction amount.
3. **The `CASHFLOW: <amount>;` colon-suffix** `add.component.ts` appends after a Sell Investment (a display artifact recomputing profit for that one workflow) is not reproduced by the typed action's generator — see the dialect note above.

## Worked example

A share-kind Grow project titled "MSFT" already holds 5 shares at €2.00 (`priceMinor` 200). `POST /grow/{id}/buy` with `{quantity: 10, priceMinor: 25000}`:

- `comment` = `"Buy Share MSFT 10 x 250;"`.
- `transactionAmountMinor` = -250000 (10 × 25000, no financing attached).
- The standalone Share's `quantity` becomes 15, `priceMinor` becomes 25000 (the new price, matching `updateShare()`'s own "always overwrite price" behavior).
- The embedded `Grow.share` copy is synced to the same `{quantity: 15, priceMinor: 25000}`, `Grow.amount` increases by 250000, and `Grow.status` becomes `"bought"`.

If the same buy also attached `liabilitie: {loanMinor: 100000, creditMinor: 5000}`: `comment` becomes `"Liabilitie 1000 50; Buy Share MSFT 10 x 250;"`, `transactionAmountMinor` becomes -150000 (250000 − 100000), `Grow.amount` increases by only 150000, and a standalone Liability tagged `MSFT` (or an existing one with that tag) accumulates `amountMinor +100000`/`creditMinor +5000` — reflected onto `Grow.liabilitie` too.
